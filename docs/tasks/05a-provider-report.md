# Task 5a: Codex proposal provider

`CodexProvider().propose(prompt, schema, artifact_dir, timeout_seconds=180)` runs one structured proposal through the installed Codex CLI. The default requested model is `gpt-6-astra` with medium reasoning. It resolves the npm Node entry point through `PATH` on Windows, or a directly executable `codex`, and launches with an argument vector and `shell=False`. It checks for an existing ChatGPT login, removes inherited API-key override variables from the child environment, and never reads or changes credentials or global Codex settings.

The call uses `--ephemeral`, read-only sandbox, `--ignore-user-config`, disabled shell/apps/plugins/browser/computer/multi-agent/memory/image features, disabled web search, and a strict JSON output schema. It records prompt, schema, event JSONL, output, stderr, status, hashes, requested model, CLI version, authentication method, elapsed time, and token usage under the supplied artifact directory. Dollar charge is `null`: the event protocol supplies token usage but no invoice. The event stream does not confirm the model actually selected by the service, so `requested_model` is explicitly a request. `ProviderError.artifact_path` points to persisted failure evidence. A deadline terminates the owned process tree (Windows Job Object with kill-on-close, POSIX process group), retains partial output with a bounded drain, and records `timed_out`. A Windows startup gate joins the Job Object before it starts the CLI, so descendants remain owned even when the launcher exits first.
