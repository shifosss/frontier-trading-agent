# Task 5: bounded model research and frozen observations

The model campaign accepts one or two schema-constrained proposals per campaign through the existing ChatGPT Codex CLI provider. It freezes the dataset manifest, execution costs, run defaults, code identity, and proposal schema before the first call. Every call counts, including rejected, duplicate, and failed attempts. The nine proposal fields are typed; only trend and reversion templates become `StrategyConfig`. The proposal cannot change costs, raw-price basis, signal timing, fill timing, or executable code. Unsupported `required_inputs` receive precise feedback and use the remaining call budget. An accepted proposal runs the deterministic Nautilus replay, and its actual return, drawdown, trade count, fees, slippage, and evidence label go into the next prompt. All attempts and provider events are persisted. Campaign labels explicitly exclude alpha proof, untouched holdouts, hidden isolation, and DSR.

`freeze_run(run_record, artifact_root)` accepts a completed replay whose result artifact agrees with the registry record and current code identity. It stores an immutable frozen configuration, source dataset manifest, strategy identity, source run ID, and code identity. `observe(frozen_id, dataset_id, data_root, artifact_root)` requires a different dataset identity with the same interval and instrument identities, all old per-instrument event times as a prefix, and at least one appended event already available at the actual observation time. It reads only bars and FX available at the actual current time. For daily and hourly data, the next eligible opening must be strictly after signal availability. It records a target signal or a no-rebalance state, never a broker order or fabricated fill. An observation is deduplicated by strategy parameters, original source history, implementation identity, and input event times. Cosmetic renaming does not create a new strategy. The observation handler and replay both bind their source versions, so changed code cannot silently inherit an earlier decision record. A prospective label requires the source to have been retrieved and ingested by `as_of` and every next eligible opening to lie in the future; stale data is `historical_only`. Future code drift rejects the frozen artifact until a replay is rerun under current code.

Validation: `.venv\Scripts\python.exe -m pytest -q tests/test_research.py tests/test_observation.py` passed 6 tests. They cover bounded repair after unsupported input, actual engine feedback, duplicate counting, immutable freeze, a new appended dataset, idempotency, rejection of interval/universe/history/code drift, the hourly opening timing rule, passive warmup parity with replay, and future-dated provenance rejection. Ruff checks pass. The replay layer emits a Pandas `Timestamp.utcnow` deprecation warning during these tests; the test results remain successful.
