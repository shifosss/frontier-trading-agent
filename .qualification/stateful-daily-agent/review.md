## Spec review

No blocking implementation finding in the supported `replay_candidate` workflow. Fees enter both reservation and next-close affordability, while exits charge the retained original quantity against the documented synthetic adjusted notional. Receivable maturity remains independent of chunk boundaries. Negative liquidation proceeds consume existing settled cash or invalidate the chunk; the wrapper does not commit an incomplete transition.

Streaming state preserves insertion-ordered positions, pending orders, receivables and exact next index; the fixed overall end controls trade eligibility rather than the chunk end. Journal transactions commit state and outputs together, check cursor/state continuity, and are protected by a separate SQLite writer transaction that spans chunk commits. Completed replay requests are idempotent. Invocation requests and failures after request registration are retained. A process killed before an exception handler can leave a durable attempt marked running, which preserves evidence rather than inventing completion.

The wrapper checks model target chronology and saved code/data/account/policy identities. It verifies the original capture and normalization through one `load_saved_history` invocation, preserves original feature warmup, reconstructs original evidence by changing only the signal date, and uses persisted heads without refitting. Replay identity also includes settlement implementation. There is no operator database, broker submission, transfer, authentication, spending or promotion path in the added workflow. Paper-file immutability remains a root qualification check rather than a claim independently established by this static review.

The parent-provided default differential evidence is corroborated by `daily-policy-differential.json`: 240 cases and 69,491 trades with exact arrays/trades/fees/activity/state/metrics against f354e04. Read the 36 profile/horizon/chunk JSON-resume cases and actual SQLite/restart failure cases; did not rerun their already-passing suite. Aggregate chunk fee sums appropriately allow floating grouping differences while paths/trades/state are exact. Genuine earlier-model/later-capture persistent versus one-shot qualification was still running at review time and remains an acceptance gate, not silently passed by synthetic nonempty trades.

Forecast diagnostics consistently identify reused calibration, training-selected ensemble weights, model convergence warnings, sampled cross-sectional results rather than portfolio returns, and lack of untouched future qualification. Current-tariff counterfactuals, missing fee coverage, cent-ceiling convention and adjusted-share limitations are explicit. No claim of universal or established all-in profitability was found.

## Quality review and concrete nonblocking observation

The additions reuse the existing scorer, planner, simulator, saved model loader and source normalization. Cost arithmetic is isolated in a small immutable profile. Persistence and report generation are separated clearly; the report is explicitly a regenerable view. Tests include independent fee examples, exact affordability boundaries, changed chunk sizes, recovery after a durable commit and actual writer exclusion. No material readability or correctness blocker found in the intended immutable-source wrapper.

**Private simulator input-immutability contract needs explicit wording.** In `short_horizon_study.py`, streaming `scope` hashes strategy/horizon/end/symbol/session layout/cost/correlation limit, but not market values or custom signal arrays. A targeted reproduction processed sessions 0..1 of the existing three-session-hold fixture, doubled `market['adjusted'][2, 0]`, then resumed session 2. It returned `complete` with the same scope and equity 2389.2200000000003 instead of 1999.22. Thus the engine alone does not reject same-layout source-value mutation. Recommend its docstring explicitly require immutable market/signal contents and say scope checks layout/policy/cursor, or accept a caller-supplied verified content identity if stronger enforcement is later required. This is not a demonstrated wrapper bypass: `replay_candidate` independently revalidates the immutable capture/data and code identities on each invocation. Rehashing multi-gigabyte matrices per chunk is unnecessary to resolve the documentation ambiguity.

## Review conclusion

Implementation is acceptable for the documented isolated, fixed-capture historical rehearsal, subject to completing the genuine earlier-model replay gate and root final verification. Preserve the private-engine contract clarification and pending economic qualification explicitly. The only new executed check in this review was the changed-market resume reproduction above; no previously passed broad test suite was repeated.
