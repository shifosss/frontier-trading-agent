# Intraday opening source qualification

Source-only capture for AAPL, MSFT, F, T, HRL, BANF and SPY. 2016 is warmup; 2017–2025 is the declared later evaluation window. No strategy returns or trading operations are computed here. `request.json`, `calendar.json`, `coverage-manifest.json` and `implementation.json` are frozen before acquisition.

The exact XNYS calendar has 2,514 sessions and 17,598 symbol/session cells, totaling 6,836,760 regular-minute slots. Every requested cell stays in the denominator. Separate missing intervals, malformed/invalid records, duplicate timestamps, opening-hour completeness, and exact entry/exit minute availability are reported. A missing bar can mean no eligible trade, a halt or a source problem; it is never a synthetic zero-volume bar.

One serial request chain per actual regular session uses raw SIP, USD, explicit asof=session and 10,000-row pages. API endpoints are fixed to the historical data host. Start is inclusive open; inclusive API end is close minus one second. Pagination follows the returned token even for short or empty pages. The original 2024-11-29 AAPL/MSFT minute fixture is hash-verified and reused; that day's new request contains only the other five symbols. No completed successful page is deliberately requested again. Each attempt, failure, raw response, response date, capture time and hash remains preserved. A separate Windows byte lock prevents duplicate capture workers.

Alpaca's [historical-bar contract](https://docs.alpaca.markets/us/reference/stockbars) defines inclusive request bounds, symbol-first pagination, raw adjustment and entity mapping by `asof`. That mapping is vendor-supplied, not a historical membership file or independently verified issuer identifier. The [aggregation FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) defines minute timestamps as interval starts and explains that trade conditions can prevent a minute bar from being emitted. Closing-auction minutes at the exact session close are excluded; these data are not asserted to reproduce official daily OHLCV. VWAP is preserved as supplied and not used to infer executable prices.

The [Basic access table](https://docs.alpaca.markets/us/docs/about-market-data-api) lists history since 2016, 200 calls/minute and the latest15-minute restriction. This capture caps itself at100/minute and never queries recent data. A 09:30–10:30 signal would therefore be eligible no earlier than10:46ET after the15-minute restriction and one minute for processing. These are revised historical bars retrieved now, not original publication timestamps or proof of real-time entitlement.

The independently checked calendar anchors are the [2024 Thanksgiving early close](https://www.nasdaqtrader.com/TraderNews.aspx?id=UTP2024-16), [2018 Bush closure](https://ir.nasdaq.com/news-releases/news-release-details/nasdaq-announces-closure-its-us-markets-honor-national-day), [2025 Carter closure](https://ir.nasdaq.com/node/108411/pdf), and the March2016 New York DST change. Package versions and the exact UTC session schedule are retained. These anchor checks do not claim an independent exchange-notice audit of every calendar date.

`fixture-test-results.json` records the offline cache/pagination/interruption/coverage tests. Start or resume with `.venv/Scripts/python.exe -B -X utf8 .qualification/intraday-opening20260928/operational_runner.py`; `--max-new-sessions 2` bounds the initial sanity pass. The same command reuses the same frozen request and completed pages. Do not change implementation/request bytes during a capture. Inspect `capture.lock`, actual PID/command, append-only stdout and the completed coverage manifest before another launch. A transport-complete capture can still contain unusable signal or execution cells. Broader membership, point-in-time revisions, corporate-action completeness and executable fills remain unqualified.
